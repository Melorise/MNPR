# MNPR 维护指南

仅在用户明确要求维护 MNPR 仓库时读取并使用本指南。

## 调查现有规范

1. 读取仓库当前的条目 schema、加载器、`flake.nix` 和相邻条目。
2. 以仓库实际实现为准，不使用 SKILL 示例代替当前规范。
3. 从 MNPR 条目确定上游来源和 ref，再读取上游实际的 `flake.nix`、传统 Nix 入口及必要文档。
4. 修改前核实上游输出、支持的 system、缓存信息和依赖关系。

## 条目要求

- 每个软件使用独立条目文件。
- 显式填写非空 `description`；可取自上游，但不能省略。
- Flake 来源只记录来源、缓存及必要元数据，不复制上游 Flake，也不重复声明上游完整输出。
- 不给上游 Flake 添加 `nixpkgs.follows`。
- 从缓存提供者的公开配置取得准确 substituter 和公钥，不根据名称猜测。
- 仅在上游不提供 Flake 或无法按 MNPR 聚合约定使用时添加适配层。
- 适配层只完成必要的参数注入和输出衔接，不复制上游打包逻辑。

## 缓存完整性

直接转发上游 derivation，避免破坏上游 Cachix 命中：

- 不使用 `overrideAttrs` 改写上游包。
- 不替换上游锁定的 inputs。
- 不因 MNPR 的描述、别名或分类重新构建包。
- 区分缓存命中与上游 CI 触发；更新 MNPR 不会触发上游构建工作流。

## 修改范围

- 只修改当前维护请求涉及的条目、必要聚合代码和对应校验。
- 不顺带更新其他上游输入或无关锁定。
- 删除条目前，核实其聚合输出、缓存配置、依赖和文档引用。
- 对存在依赖关系的传统 Nix 适配条目，先确认删除或改名不会破坏其他条目。

## 验证

按照仓库当前提供的流程完成验证：

1. 格式化修改过的 Nix 文件。
2. 检查所有条目 schema，尤其是必需的 `description`。
3. 求值修改条目的目标 system 和输出路径。
4. 运行仓库已有的 Flake 检查。
5. 对适配层至少验证其依赖注入和 derivation 求值。
6. 不为了验证而更新无关 inputs。

完成后报告修改的条目、上游来源与 ref、导出的输出、缓存变化和验证结果。
